the builder’s corner

What’s behind this board

Cairn isn’t a company, and this page isn’t a pitch. It’s a work sample — the pattern extracted from a knowledge system I built and operate every day, genericized so anyone can run it. The site exists to show how I think and what I ship.

  • 69 skills in the source system
  • 5 agent roles with written boundaries
  • 1 custom MCP server, built on Anthropic’s SDK
  • ~50 API endpoints behind one auth layer

The habits that carried into the kit

  • Writes wait for a human. The approval gate exists because my first version failed: approvals lived in memory with a ten-minute expiry, so a restart silently dropped them and my phone never saw them. The redesign — durable files, notification on creation, resolvable from anywhere — is the one in the kit.
  • Nothing is ever deleted. The log is append-only; corrections are new entries. An audit trail you can edit isn’t an audit trail.
  • A skill isn’t a prompt. Every one ships a written procedure, declared parameters, and an acceptance test — so quality doesn’t depend on typing the right words on the right day.
  • The system reports its own blind spots. Scheduled checks diagnose stale indexes, capped batches, and gated actions with no approval line — and flag them instead of waiting to be asked.

Before the AI work

I ran Microsoft 365 for a ~700-person organization in GCC High, under CMMC and NIST 800-171 — identity, permissions, compliance, and training people through change. The taped photo on this board is where that background and the AI work meet.

Those are the two halves of putting AI into a business safely — and the point of this board is that I’ve done both.

Starter kit — running in 10 minutes, no API key

A zip of markdown files and three shell scripts. Unzip it, run init.sh, and a plain POSIX script validates the vault and prints a health report. The first success involves no model, no key, and no account — deliberately, so the structure earns trust before any AI touches it.

$ ./scripts/init.sh
$ ./scripts/check.sh   # exit 0 = healthy vault

That ten-minute claim isn’t copy — it was tested from a fresh unzip, and check.sh refuses to package a broken vault.

Skill catalog

A skill isn’t a prompt. Every catalog item ships three files — a written procedure, declared parameters, and an acceptance test — so deploying it for the next person is configuration, not rework.

The method comes from the source system, where 69 skills run this way. The kit ships eight of them, genericized: ingestion, curation, health checks, chronicle writing, and the rest of the loop’s moving parts.

The acceptance test is the part most people skip — and the part that makes a skill deployable to a client instead of demoable to a room.

the guardrail stickies

Guardrails

  • Approval gate — writes wait for a human, and the wait itself is logged before anything happens. Autonomy earns trust by being interruptible.
  • Health checks — a stale routing index, a batch that stopped at a cap and was never finished, two notes that quietly became duplicates, a gated action with no matching approval line. The vault names its own findings rather than waiting to be asked.
  • One vault, many AIs — two adapter files sit over one rulebook. A new runtime means a new adapter, not a reorganized vault — curate once, serve every assistant.
  • Hard limits — autonomous skills carry an item cap and an error cap, so a misbehaving run stops itself instead of running away.

Every one of these exists because something went wrong once in the source system and I decided it would never go wrong silently again.

The principle

The vault is a pattern, not a product. Your knowledge should outlive your tools.

That’s why this site sells nothing. The kit is MIT-licensed markdown and shell scripts; the mapping page shows how the same pattern lands on a Microsoft 365 tenant with nothing new to buy. If the tools change next year — and they will — the vault doesn’t care.

It’s also why the board you’re looking at is a work sample rather than a landing page: the interesting thing was never the product. It’s the thinking, written down, in a form you can run.
