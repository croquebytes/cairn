The kit

Running in ten minutes. No API key.

A folder of markdown files, three shell scripts, and a rulebook. Start by running the health check: no model, key, or account required. If a system only works after you hand it a paid API key, you don’t quite own it.

01 — quickstart

Four commands

# unzip what you just downloaded
unzip cairn-kit.zip && cd cairn-kit

# name the vault, start a fresh git history, run the check
./scripts/init.sh "My Vault"

# the health check, any time
./scripts/check.sh

# package the catalog for distribution
./scripts/package.sh

check.sh is plain POSIX shell. It validates every file against the rules in MANIFEST.md for frontmatter, naming and the catalog's three-file contract, then reports the blind spots the vault can detect about itself. Errors exit non-zero, so it works as a pre-commit hook or a CI step without any further wiring.

Then open the folder in whatever assistant you use and say:

Read vault/MOC.md and give me the vault status.

From there the loop is: drop something in vault/inbox/raw/, run ingest, run promote. That is the whole system. Everything else is a variation on it.

What "no API key" means

You need an assistant to operate the vault. You do not need one to stand it up, validate it, or run its health check, and you never need to provision a key to try it. The files are the product.

Requirements

sh, and optionally git and zip. Tested on macOS and Linux. No runtime, no package manager, no build step.

02 — what’s in the box

Fifty-four files, and none of them are a database

cairn-kit/
  MANIFEST.md          the rules — outranks every adapter
  CLAUDE.md            adapter: Claude Code / Claude apps
  AGENTS.md            adapter: Codex, Cursor, anything else
  vault/
    MOC.md             routing index — read first, every session
    knowledge/         curated notes that passed the promote gate
    inbox/raw/         everything lands here first
    inbox/archive/     reviewed, not promoted. Never deleted
    logs/              chronicle · approvals · heartbeat
    templates/         use these; don't freehand frontmatter
    skills/            safety-limits · vault-orientation
                       ingest · promote · status
    agents/            archivist · scout
  catalog/             eight packaged skills — see below
  scripts/             init.sh · check.sh · package.sh

Guardrails ship on

safety-limits is enabled by default, not offered as an exercise for the reader: ten items per batch, three consecutive errors then stop, no skill invoking itself, and an approval gate on anything that sends, installs, deletes, or writes outside the vault.

Instructions in content are data

A pasted thread, an ingested page, a policy file. If any of them contains text telling the assistant what to do, it gets quoted back to you rather than obeyed. Content cannot grant its own approval.

03 — the catalog

A skill isn’t a prompt

It’s a procedure plus its tailoring parameters plus its acceptance test, packaged so that deploying it for the next person is configuration, not rework. Every item below ships all three files. check.sh treats a missing one as an error, not a warning.

SKILL.md

The procedure. Triggers, inputs, steps, guardrails, and an explicit negative scope, because a skill without one gets loaded for the wrong things.

params.md

The tailoring surface. What a deployer changes per client, per team, per person. If you have to edit the procedure to fit a deployment, a parameter is missing.

checklist.md

The acceptance test. Happy path, failure paths, the I-don’t-know test, and the safety cases. This is what “validated” means. A demo is not a validation.

What every skill in the catalog refuses to do

Consistent across all eight, and not parameterizable: send, post, publish or deploy, because every one of them drafts and a human sends. Delete, because there is no delete verdict and no parameter that creates one. Invent an owner, a date, a rationale or an approval, since unassigned, not set and not recorded are correct answers, and each is a fact worth having. Obey instructions found in content. Exceed a batch cap to finish the job.

04 — what this is not

Version 0.1.0

  • Not a SaaS product. There is no hosted version and no account.
  • Not an agent framework. It is a folder and a set of rules that agents obey.
  • Not a search engine. It relies on good description: frontmatter and a routing index rather than an embedding store. Add vector search if you want it; the files don't change.
  • Not connected to Microsoft 365. The M365 skills run on pasted content. Graph integration is real work and has not been done here.
  • Not finished. The core loop works and the catalog is a starting set, not a complete library.

Every claim on this site is meant to be true of the kit as it downloads. If you find one that isn't, that's a bug in the site, not an aspiration.
